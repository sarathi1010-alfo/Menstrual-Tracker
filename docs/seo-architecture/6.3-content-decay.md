# Content Decay Prevention System

When dealing with 1,000+ programmatic pages, some will naturally lose traffic over time due to algorithmic changes or competitor updates.

## 1. Detection Workflow (Run Monthly)
1. In GSC, compare the Last 28 Days vs. Previous 28 Days.
2. Filter for `URL contains /tools/` or `/guides/`.
3. Sort by `Impressions Difference` (Ascending).
4. Any page with a negative impression drop > 25% is marked "Decaying".

## 2. Triage Matrix

| Severity | Definition | Action Plan |
| :--- | :--- | :--- |
| **Mild** | < 10% drop, ranking stable. | Natural variance. Do nothing. |
| **Moderate** | 10-25% drop, CTR is dropping. | Update the `seo-metadata.ts` for that cluster to make the title more enticing. |
| **Severe** | > 25% drop, ranking fell from Page 1 to Page 2. | Trigger a full "Freshness Update" (see below). |

## 3. The "Freshness Update" Checklist
To signal a genuine update to Google (not just changing the `lastModified` date in the sitemap):
- **For Hubs (MDX):** Add a new H2 section discussing a recent trend (e.g., a new wearable tech for ovulation tracking). Update the date in the MDX frontmatter.
- **For Tools:** Expand the `pSeoData.json` FAQ array from 2 questions to 4 questions. Ensure the new questions target the specific queries where impressions were lost.
- **Internal Linking:** Point a link from the Homepage or a high-traffic Hub directly to the decaying page for 2 weeks to force a re-crawl and inject authority.

## 4. Mistakes to Avoid
- Do not change the URL Slug of a decaying page (you will lose all history).
- Do not just update the `lastModified` sitemap tag without changing the actual page DOM. Google ignores "fake" freshness.
