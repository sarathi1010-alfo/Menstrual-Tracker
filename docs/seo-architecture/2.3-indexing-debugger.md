# Indexing Failure Debugger

When Google Search Console (GSC) flags indexing issues on our programmatic tools, use this guide to diagnose and fix them specifically within our Next.js App Router setup.

---

### 1. "Crawled - currently not indexed"
- **Cause:** Google successfully downloaded the page but decided not to index it. Usually indicates thin content, duplicate content, or low perceived value.
- **Diagnosis:** Compare the tool page to others. Is the schema missing? Is the FAQ section too brief? Are there too few internal links pointing to it?
- **Fix:** Enhance the JSON `pSeoData.json` for that tool. Add 2 more specific FAQs. Ensure a related hub page links to it. Request re-indexing.

### 2. "Discovered - currently not indexed"
- **Cause:** Google saw the URL (likely in the sitemap or via an internal link) but the server was overloaded, or Google's crawl budget for the site was exhausted.
- **Diagnosis:** Check GSC Crawl Stats. Is the average response time spiking?
- **Fix:** Ensure the tool is statically generated (`generateStaticParams`). If using Vercel, check for cold starts on any middleware. Wait 1 week.

### 3. "Duplicate, Google chose different canonical than user"
- **Cause:** We have two tools that are too semantically similar (e.g., "Period Tracker" and "Menstrual Tracker").
- **Diagnosis:** Search GSC for the URL. Look at the "Google-selected canonical".
- **Fix:** If the tools serve the exact same function, merge them. 301 redirect the duplicate to the canonical URL.

### 4. "Page with redirect"
- **Cause:** The sitemap or internal links point to a URL that redirects (e.g., missing a trailing slash, or `http` vs `https`).
- **Diagnosis:** Check the exact URL in the `href` of the internal link vs the final resolved URL in the browser.
- **Fix:** Update `absoluteUrl` in `src/lib/seo.ts` to ensure strict formatting. Update `pSeoData.json` slugs to match exactly.

### 5. "Blocked by robots.txt"
- **Cause:** The page path matches a `Disallow` rule in `public/robots.txt` or `src/app/robots.ts`.
- **Diagnosis:** Check `src/app/robots.ts`. Are we accidentally blocking `/tools/`?
- **Fix:** Remove the conflicting rule. Test via GSC robots.txt tester.

### 6. "Server error (5xx)"
- **Cause:** The Next.js server crashed when Googlebot requested the page.
- **Diagnosis:** Check Vercel runtime logs for the exact timestamp of the crawl. Look for unhandled promise rejections or missing data in `generateMetadata`.
- **Fix:** Add fallback checks in `src/app/tools/[slug]/page.tsx` (`if (!pageData) notFound();`). Ensure SSG prevents runtime 500s.

### 7. "Alternate page with proper canonical tag"
- **Cause:** This is usually **expected behavior** if Google crawled a URL parameter (e.g., `?source=widget`) but the page canonicalized back to the clean URL.
- **Diagnosis:** Verify the listed URL has parameters or trailing slashes.
- **Fix:** No action needed unless the clean URL is *also* not indexed.
