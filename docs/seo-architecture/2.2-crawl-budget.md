# Crawl Budget Optimization Plan: LunaCycle

## Principles for Next.js/Vercel Stack
Because we are aiming for 1,000+ programmatic pages, Googlebot will hit crawl limits. If our server response is slow or our URLs are deep, Google will stop crawling before indexing our tools.

## 1. Prioritized Optimization Checklist

1. **Strict SSG for Tools:** Tools must export `generateStaticParams()` so Vercel serves them from the edge cache instantly (TTFB < 50ms).
2. **Block Vercel Defaults:** Ensure `robots.txt` or middleware blocks `.vercel.app` domains from indexing to prevent duplicate domain crawling.
3. **Flat Directory:** Keep tools at `/[cluster]/[slug]` max. No deep nesting.
4. **Kill Query Params:** Calculations happen via `localStorage` and JS state. **Do not use URL parameters** (`?cycle=28`) to store state, as this creates millions of infinite URLs for Googlebot to crawl.
5. **XML Sitemap Indexing:** Use `<sitemapindex>` (implemented) to partition our site. Google crawls segmented sitemaps faster than one massive one.
6. **Hub-to-Spoke Pagerank:** Ensure the homepage links to Hubs, and Hubs link to Tools. Googlebot crawls high-authority pages more often.

## 2. Vercel-Specific Performance Checklist
- [ ] Ensure Next.js Image Optimization is used sparingly on tools (we prefer SVG/CSS for our aesthetic) to save compute.
- [ ] Check Vercel logs for 5xx errors. 5xx errors drastically reduce crawl budget.
- [ ] Verify `x-vercel-cache: HIT` header on programmatic pages to confirm edge caching.

## 3. Monitoring Plan (GSC Weekly)
- **Crawl Stats Report:** Check "Host status" for 5xx errors or DNS timeouts.
- **Average Response Time:** Must remain under 300ms in GSC Crawl Stats.
- **Discovered - Currently not indexed:** If this number spikes, it means Google found the URLs via sitemap/links but decided crawling them wasn't worth the budget/time. Indicates performance or thin-content issues.
