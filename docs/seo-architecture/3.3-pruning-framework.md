# Content Pruning Decision Framework

With programmatic SEO, not every generated page will succeed. Index bloat (too many low-value pages) damages overall site authority. This framework determines when to kill, merge, or improve a page.

## Evaluation Criteria (Run every 3 months)
A page is eligible for review if it has been **live for > 6 months**.

### The Scoring Matrix

| Scenario | Data Profile (GSC & GA4) | Decision | Action |
| :--- | :--- | :--- | :--- |
| **The Ghost** | 0-100 Impressions/mo, 0 Clicks, 0 internal links pointing to it. | **PRUNE** | Remove from `pSeoData.json`. Return 410 Gone (preferred over 404). |
| **The Cannibal** | Ranks for the exact same queries as a better-performing sibling tool. | **CONSOLIDATE** | Pick the winner. 301 Redirect the loser to the winner. Remove loser from sitemap. |
| **The Missed Swing** | 5,000+ Impressions, Position 5-15, CTR < 0.5%. | **OPTIMIZE** | Do not prune! The page is relevant. Update the Title Tag, H1, and add schema. |
| **The Bounce Trap** | High Clicks, but GA4 shows < 10s Engagement Time and 90% Bounce Rate. | **REBUILD** | The intent is mismatched or the tool UI is broken. Fix the tool logic or rewrite the intro to match user expectation. |

## Execution SOP: Pruning a Tool
1. Remove the JSON entry from `src/data/pSeoData.json`.
2. Ensure no hardcoded internal links still point to that slug in other Markdown files or Components.
3. Update `next.config.js` with a permanent 301 Redirect (if consolidating to another tool) or let it naturally 404/410 (if completely deleting).
4. Do **not** submit the dead URL to GSC manually; let Googlebot discover the redirect/404 naturally via the sitemap update.
