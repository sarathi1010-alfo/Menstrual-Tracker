# Rendering Strategy: CycleHub Programmatic SEO

## Core Principle
"Serve fast, crawl fast." In a Next.js App Router environment targeting massive programmatic scale, selecting the correct rendering strategy ensures rapid crawling and indexing, preserving our crawl budget.

## Strategy Matrix

| Tool / Page Type | Recommended Strategy | Rationale | Next.js App Router Mechanism |
| :--- | :--- | :--- | :--- |
| **Static Hub/Guide ("How to Track Ovulation")** | SSG (Static Site Generation) | Content is static, rarely changes. Needs fastest possible TTFB for maximum Core Web Vitals score. | `export const dynamic = 'force-static'` or implicitly via lack of dynamic functions. |
| **Programmatic Tool Template (Calculators, Validators)** | SSG with Client-Side Hydration | The core shell, metadata, and schemas are identical for every user visiting `/tools/ovulation-calculator`. The actual calculation happens client-side using `localStorage`. | `export async function generateStaticParams()` + Client Components (`"use client"`) for interactivity. |
| **Semi-Dynamic Content Hub (e.g., "Trending Cycles")** | ISR (Incremental Static Regeneration) | Needs to be fast like SSG, but update periodically without full rebuilds. | `export const revalidate = 3600` (rebuilds background every hour). |
| **Personalized User Dashboard (Cycle Calendar View)** | Client-Side Rendering (CSR) | Purely private data read from `localStorage`. No SEO value; shouldn't be indexed. | Next.js Client Component reading from context on mount. |

## Implementation Patterns

### 1. Static Site Generation (SSG) for Informational Guides
```tsx
// src/app/guides/[slug]/page.tsx
import { notFound } from 'next/navigation';
import { getGuideData } from '@/lib/mdx';

export async function generateStaticParams() {
  const slugs = ['understanding-your-cycle', 'how-to-track-ovulation'];
  return slugs.map((slug) => ({ slug }));
}

export default async function GuidePage({ params }: { params: { slug: string } }) {
  const data = await getGuideData(params.slug);
  if (!data) notFound();

  return <article>{data.content}</article>;
}
```

### 2. SSG + Client Hydration for Tools (The "CycleHub" Model)
Because CycleHub mandates strict privacy (no backend data) and all calculations occur in the browser, the **SEO-critical shell must be statically generated**, while the calculator itself runs entirely client-side.

```tsx
// src/app/tools/[slug]/page.tsx
import seoData from '@/data/pSeoData.json';
import { OvulationCalculatorClient } from '@/components/tools/OvulationCalculatorClient';

// 1. Generate URLs statically at build time
export async function generateStaticParams() {
  return seoData.map((page) => ({ slug: page.slug }));
}

// 2. Generate SEO metadata statically
export async function generateMetadata({ params }) {
  const pageData = seoData.find((p) => p.slug === params.slug);
  return { title: pageData.title, description: pageData.description };
}

// 3. Render Server Component shell
export default async function ToolPage({ params }) {
  const pageData = seoData.find((p) => p.slug === params.slug);

  return (
    <main>
      <h1>{pageData.h1}</h1>
      <p>{pageData.intro}</p>

      {/* 4. Mount interactive client component */}
      <OvulationCalculatorClient />
    </main>
  );
}
```

### 3. Incremental Static Regeneration (ISR)
For aggregated pages that might update periodically (e.g., if we ever pull anonymized public stats or cycle trends).

```tsx
// src/app/trends/page.tsx
export const revalidate = 86400; // Revalidate daily (in seconds)

export default async function TrendsPage() {
  // This fetch happens at build time, and then in the background once a day
  const data = await fetch('https://api.example.com/trends').then(res => res.json());

  return <div>{/* Render trends */}</div>;
}
```
